
 Authentication Learning Project Plan

 Structure: "AuthCore" - Sprint-Based Auth Service

 Project: Build a standalone authentication/authorization service incrementally

 Tech Stack:
 - Python 3.12 + FastAPI (already in your flake.nix)
 - httpx for testing
 - Minimal HTML (single-file templates I'll provide - you won't modify)

 8 Sprints (feature-driven, building on each other):

 Sprint 0: Foundation

 - Basic FastAPI app structure
 - Session-based authentication (cookies, session storage)
 - Login/logout flows
 - MUST-KNOW: Cookie security (HttpOnly, Secure, SameSite), session management, CSRF
 basics

 Sprint 1: JWT Authentication

 - Replace sessions with JWT tokens
 - Token signing, validation, expiration
 - Refresh token implementation
 - MUST-KNOW: JWT structure, signing algorithms, token rotation, security pitfalls

 Sprint 2: OAuth 2.0 Authorization Server

 - Implement Authorization Code Grant
 - PKCE support
 - Token endpoint, authorization endpoint
 - MUST-KNOW: OAuth roles, grant types, why PKCE matters, state parameter

 Sprint 3: OpenID Connect Layer

 - Add OIDC on top of OAuth 2.0
 - ID tokens, UserInfo endpoint
 - Discovery document (.well-known/openid-configuration)
 - MUST-KNOW: OAuth vs OIDC, ID token vs access token, claims

 Sprint 4: Multi-Factor Authentication

 - TOTP (Time-based OTP) implementation
 - MFA enrollment and verification flows
 - MUST-KNOW: TOTP algorithms, backup codes, MFA UX patterns

 Sprint 5: Role-Based Access Control

 - Implement RBAC system
 - Permission scopes in tokens
 - Resource server validation
 - MUST-KNOW: RBAC vs ABAC, scope design, token introspection

 Sprint 6: Social Login Integration

 - Add "Login with GitHub" (or Google)
 - Federation patterns
 - MUST-KNOW: Identity federation, trust relationships, token exchange

 Sprint 7: WebAuthn / Passwordless

 - Implement FIDO2/WebAuthn
 - Passkey registration and authentication
 - MUST-KNOW: Public key cryptography in auth, challenge-response, attestation

 Deliverables:
 - plan.md (similar to your AWS project) with sprint tracking
 - Working auth service that demonstrates all major patterns
 - Test clients (curl commands + Python httpx scripts)
 - Minimal HTML pages to visualize flows (I scaffold these)

 Mini-Projects (interspersed as needed):
 - mTLS client/server (1-2 hours)
 - SAML basics (if you need enterprise patterns)
 - Certificate inspection and validation

 3. Begin Sprint 0 with session-based auth

 This approach teaches you authentication from first principles while building something
 real and reusable.
