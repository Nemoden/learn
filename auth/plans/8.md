
• Here’s a focused, practice-heavy plan to build strong, everyday-use authentication and
  authorization skills. It mixes small drills with one cohesive project so you can discuss
  and implement confidently.

  Week 0: Foundations (2–3 days)

  - Auth vs. AuthZ vs. Accounting: concepts, tokens vs. cookies, sessions; refresh vs.
    access tokens; password hashing (bcrypt/argon2); CSRF/XSS/Clickjacking basics.
  - Hands-on drills: hash/verify passwords; create/validate JWTs (with exp/aud/iss), sign/
    verify with HS256 vs RS256; set and read HttpOnly + SameSite cookies; build a tiny
    CSRF-protected form using same-site + origin checks.
  - Reading: OWASP ASVS sections on authentication; cheatsheets for auth, session
    management, password storage.

  Week 1: Core Web Auth (3–4 days)

  - Build “AuthN microservice” (REST/JSON): signup/login/logout, email verification flow,
    password reset, rate limiting.
  - Implement: secure cookie session; also add a token-based variant (JWT) to compare
    tradeoffs. Use refresh/access tokens with rotation and revocation list.
  - Add: per-user roles (user/admin), route guards, middleware structure.
  - Tests: unit tests for hashing, token issuance/verification; integration tests for
    signup/login/logout/refresh; simulate token replay and ensure it fails.

  Week 2: OAuth2.1 + OIDC (4–5 days)

  - Implement a minimal “OAuth client” + “resource server” + “auth server mock.”
  - Flows: Authorization Code with PKCE (public client) and without (confidential);
    understand scopes, consent, state/nonce, redirect URI validation.
  - Add OIDC: ID Token validation (nonce, aud/iss, exp), userinfo endpoint; JWKS fetch and
    key rotation (cache keys; handle kid miss).
  - Drill: break tokens (wrong aud/iss, expired, swapped nonce) and ensure validation
    rejects them. Replay auth code and confirm it fails.

  Week 3: Real-World Hardenings (3–4 days)

  - Account security: MFA (TOTP), backup codes, WebAuthn/U2F intro; device/refresh token
    binding; session inactivity/absolute timeouts.
  - Defense: lockout/backoff strategies; IP/device fingerprint basics; secure remember-me
    with rotating tokens; audit logs.
  - Privacy and compliance: minimal PII storage, GDPR “right to forget” flow; secrets
    management (.env, KMS); secure logging (no secrets).
  - Tests: add MFA enrollment/verification paths; regression tests for lockout and backoff.

  Week 4: Productionizing (3–4 days)

  - Observability: structured auth logs, correlation IDs; metrics for login failure rates,
    token refresh volumes; alerts on anomalies.
  - Ops: key rotation playbook (JWT signing keys); secrets rotation; incident runbook for
    token leak.
  - Performance: cache JWKS, reduce DB round-trips for sessions, tune indexes on session/
    refresh tables.
  - SSO: integrate with a real IdP (Okta/Auth0/Keycloak) as an OAuth client; map external
    roles/groups to app roles; JIT provisioning.

  Capstone Project (spans Weeks 1–4)

  - Build a small “Team Tasks” web app with:
      - Local auth: signup/login/logout, email verification, password reset.
      - JWT access + rotating refresh cookies; revocation list.
      - RBAC: user/admin; route guards on API and UI.
      - MFA (TOTP) and backup codes.
      - OAuth/OIDC login with an external IdP; map scopes/groups to roles.
      - Audit log and admin panel to view sessions, revoke tokens, rotate keys.
      - Tests (unit + integration) covering flows, replays, lockouts, and key rotation.

  Daily Practice Cadence

  - Morning: 45–60 min drills (hashing, JWT verify, CSRF check, token rotation).
  - Build block: 2–3 hours implementing one feature end-to-end with tests.

  - Reflection: 10–15 min write-up of pitfalls and tradeoffs (cookies vs. JWT; PKCE vs.
    client secret; RS256 vs HS256; remember-me design).

  Reference Stack (pick one and stick with it)

  - Backend: Node/Express or FastAPI; Postgres.
  - Auth libs: jose/oidc-provider (Node) or authlib/pyjwt (Python).
  - Tests: supertest/pytest; use local Redis for rate limiting/locks.

  Discussion Prep (colleague-ready)

  - Be able to explain: why rotate refresh tokens; how PKCE stops code interception;
    why SameSite=Lax + HttpOnly matters; RS256 vs HS256 tradeoffs; replay protection
    strategies; lockout vs. backoff; key rotation steps.
  - Be ready to sketch sequence diagrams for: login, refresh rotation, OAuth code flow with
    PKCE, and MFA TOTP verification.
